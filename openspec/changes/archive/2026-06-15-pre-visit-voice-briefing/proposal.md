# Proposal: pre-visit-voice-briefing

## Why

The detail view already shows a technician everything the model knows about a unit (risk score, the three prediction drivers, the 6-day trend, last-visit info, and a natural-language explanation), but reading and synthesising it takes attention the technician often does not have — they are frequently on the move before a visit. Milestone **M4a** turns that scattered data into a single spoken **pre-visit briefing**: a short, natural summary of the unit's current state plus a clear recommendation, read aloud in the browser. It is the "voice out" half of M4 (the "voice in" post-visit report is M4b) and showcases multimodal output and an in-EU LLM integration on the existing AWS deployment.

## What Changes

- Add a backend endpoint `GET /api/elevators/{id}/briefing` that assembles the unit's existing data and produces a natural-language briefing of ~4–8 sentences (shorter when the unit has little signal) ending in one or two actionable recommendations.
- Generate the text with an LLM on **Amazon Bedrock** via the **Converse API**, starting with `eu.amazon.nova-lite-v1:0` in `eu-north-1` (verified ACTIVE and invokable). Model id and region are env-configurable so switching to `eu.anthropic.claude-haiku-4-5-20251001-v1:0` is an env-var change, no code change.
- Provide a **deterministic fallback** briefing (built from the unit's fields) when the Bedrock call fails or times out, so the endpoint never returns 5xx for a valid unit.
- Add a frontend "Brief me" control on the unit detail view that fetches the briefing, displays the text, and reads it aloud via the **Web Speech API** (`speechSynthesis`), with Play/Stop and a text-only fallback when the API is unavailable.
- The briefing is **generated on demand and not persisted** — no database or schema changes.

## Capabilities

### New Capabilities

- `pre-visit-briefing`: On-demand, natural-language pre-visit briefing for a single in-scope elevator, generated by an Amazon Bedrock LLM from the unit's existing risk data with a deterministic fallback, exposed over HTTP and read aloud in the browser via the Web Speech API.

## Impact

- **New backend files**: `app/services/bedrock_client.py`, `app/services/briefing_service.py`, `app/schemas/briefing.py`
- **Modified backend files**: `app/routers/elevators.py` (new route), `app/core/config.py` (Bedrock settings), `backend/requirements*.txt` (add `boto3`)
- **New frontend files**: `frontend/src/components/VoiceBriefing.tsx`
- **Modified frontend files**: `frontend/src/pages/ElevatorDetail.tsx`, `frontend/src/types/elevator.ts`
- **API**: new `GET /api/elevators/{id}/briefing` → update `docs/api-spec.yml`
- **Data model**: none (briefing not persisted) → note in `docs/data-model.md`
- **AWS (one-time)**: production EC2 instance role needs `bedrock:InvokeModel` on the EU inference-profile ARN and the routed foundation-model ARNs. Local/manual access via the `daniel-admin` IAM user is already verified.
- **Cost/latency**: tiny input + short output; ~$0.0001/briefing on Nova Lite. Short `maxTokens`, ~5s timeout → fallback; optional in-memory per-unit cache.
