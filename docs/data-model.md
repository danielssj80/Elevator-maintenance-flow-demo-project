# Data Model

## Domain Overview

The system monitors a fleet of elevators across buildings in multiple cities. A predictive ML model scores each elevator's failure risk daily based on telemetry signals. Maintenance technicians receive prioritised visit lists and submit post-visit reports that feed back into model retraining.

---

## Entities

### Elevator

The core domain entity. Represents one physical elevator unit.

| Field | Type | Constraints | Description |
|---|---|---|---|
| `id` | `string` | PK, format `ELV-NNN` | Unique identifier |
| `building_name` | `string` | required | Name of the building |
| `building_type` | `enum` | see values | Type of building |
| `floor_count` | `integer` | ≥ 1 | Number of floors served |
| `model` | `string` | required | Commercial model name (e.g. "ThyssenKrupp MAX 3000") |
| `brand` | `enum` | `own`, `third_party` | Ownership: `own` = ThyssenKrupp fleet, `third_party` = other brands |
| `age_years` | `integer` | ≥ 0 | Years since installation |
| `risk_score` | `float` | 0.0 – 1.0 | ML model failure probability |
| `risk_level` | `enum` | `high`, `medium`, `low` | Derived from `risk_score` (see business rules) |
| `trend` | `float[]` | 6 elements, each 0.0–1.0 | Daily `risk_score` for the past 6 days (index 0 = oldest, index 5 = today) |
| `last_visit_date` | `date` | ISO 8601 (`YYYY-MM-DD`) | Date of the most recent technician visit |
| `last_visit_technician` | `string` | required | Name of the technician who last visited |
| `last_visit_notes` | `string` | required | Free-text notes from the last visit |
| `nl_explanation` | `string` | required | Natural language explanation of the current risk score generated by the model |
| `features` | `Feature[]` | exactly 3 elements | Top risk factors contributing to the score |
| `in_model_scope` | `boolean` | required | Whether this elevator is included in the predictive model |
| `hourly_trips_avg` | `integer` | ≥ 0 | Average number of trips per hour |
| `zone` | `string` | required | City or operational zone (e.g. "Madrid", "Barcelona") |

**`building_type` values:**

| Value | Description |
|---|---|
| `residential` | Apartment blocks and housing |
| `commercial` | Shopping centres and retail |
| `office` | Office buildings |
| `infrastructure` | Hospitals, airports, metro stations |

### Feature (embedded in Elevator)

Represents a single risk factor contributing to the elevator's `risk_score`. Always 3 per elevator.

| Field | Type | Constraints | Description |
|---|---|---|---|
| `name` | `string` | required | Human-readable factor name (e.g. "Vibration anomaly") |
| `impact` | `float` | 0.0 – 1.0 | Relative contribution to the risk score. Sum of all 3 impacts ≈ 1.0 |
| `value` | `string` | required | Human-readable measured value (e.g. "2.4× baseline", "168 days") |

**Known feature names (current model):**

- `Vibration anomaly` / `Vibration trend` / `Vibration`
- `Motor current deviation` / `Motor current`
- `Temperature delta` / `Temperature`
- `Door error rate` / `Door open/close errors`
- `Door cycle overrun` / `Door cycle count`
- `Days since last service`

---

### VisitReport (persisted)

Submitted by a technician after completing an elevator visit. Stored in the `visit_reports` table and queued for model retraining.

| Field | Type | Constraints | Description |
|---|---|---|---|
| `technician_name` | `string` | required | Name of the technician |
| `visit_date` | `date` | ISO 8601 (`YYYY-MM-DD`) | Date the visit took place |
| `failure_found` | `boolean` | required | Whether a failure was found during the visit |
| `components_replaced` | `string[]` | default `[]` | List of replaced components (free text) |
| `parameters_corrected` | `string[]` | default `[]` | List of corrected parameters (free text) |
| `notes` | `string` | default `""` | Additional technician notes |

## Business Rules

### Risk Level Derivation

`risk_level` is derived from `risk_score` — never stored independently from the score:

| `risk_score` range | `risk_level` |
|---|---|
| > 0.80 | `high` |
| 0.50 – 0.80 | `medium` |
| < 0.50 | `low` |

### Model Scope (`in_model_scope`)

An elevator is included in the predictive model if either:
- `brand == "own"` (ThyssenKrupp fleet, regardless of age), **or**
- `age_years <= 12` (recent enough to have reliable telemetry)

Elevators outside scope are displayed with a visual indicator and excluded from risk-based prioritisation.

### Risk Trend

The `trend` array always contains exactly 6 elements representing the daily risk score history. Index 0 is the oldest day, index 5 is today's score (equal to `risk_score`). Used to render a sparkline in the UI.

### Feature Impact Sum

The sum of `impact` values across the 3 features of an elevator always approximates 1.0. Individual impacts represent the proportional contribution of each factor to the total risk score.

## Current Data Storage

The backend uses **PostgreSQL 16** (managed by SQLAlchemy 2.x async + Alembic migrations). Tables:

| Table | Entity |
|---|---|
| `elevators` | `Elevator` (all scalar fields) |
| `elevator_features` | `Feature` (FK to `elevators.id`, cascade delete) |
| `elevator_trend_points` | trend data (FK to `elevators.id`, unique on `(elevator_id, day_index)`) |
| `visit_reports` | `VisitReport` (FK to `elevators.id`, JSONB for list fields) |

`risk_level` is derived in the service layer from `risk_score` — not stored. `trend` is stored as individual rows and assembled into a sorted array by the service.
